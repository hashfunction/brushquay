# Bristlune opt-in Store release integration review

Implementation is limited to packaging, qualification interfaces and the Windows
workflow. Product GUI/input/module/painting/PNG/KRA logic and source catalog are
unchanged. The written implementation plan is RELEASE-INTEGRATION-PLAN.md.

The default foundation path remains available. Explicit workflow_dispatch release=true
first refuses the committed null review binding, before dependency download/build.
Root supplies reviewed catalog/publication/owner mapping data using RELEASE-INPUTS.md;
this implementation does not enable source/license approval.

The release builder reuses the current native six-suite receipt, complete CMake tree,
locked source-input verification, runtime selector/materializer, exact PE reader and
existing audited SDK builder. It requires full current PE observation before any exact,
separately reviewed three-file TLS exclusion. All original notices are copied unchanged.
Both fixed identities retain BrushQuay application/update compatibility and Bristlune
1.0.1.0 naming. Separate native Windows PowerShell 5.1 processes run the existing full
installed painting/save/export/reopen/pixel oracle/normal-close/uninstall lifecycle.

The final independent exporter checks current source/tree/GitHub run/attempt, helpers,
SDK bytes/signature observations, package/container/unpacked/installed payloads,
original prepared-package records, complete five-stage window/capture snapshots,
startup and workflow-complete module records, final enforcing module gate, typed
independent pixel/file oracle, exact snapshot hashes and all owned cleanup outcomes.
Startup module capture remains an observation of the immediately activated process;
the existing final gate requires actual Qt core/platform modules. Original fixture
files are removed by their owned cleanup: export checks their original oracle records
and hashes, and does not pretend to decode deleted KRA/PNG files again.

Only the exact unsigned MSIX and export receipt are published into an exclusive final
output directory. The artifact step lists exactly these two files, success-only.
Metadata retains builder/SDK failure logs without including signing material/binaries.

  fixed identities/current workflow context, reviewed inputs and exact TLS reverse-edge
  refusals, unsigned ZIP/SDK/payload mutations and stale/partial workflow/oracle records.

- Installed readback tests: 3 cases passed, including independent mode confusion.
- Actual PowerShell production identity fixture: both modes, eight registration changes
  and three unknown modes passed. Existing lifecycle phase/cleanup, observer argument
  and actual callback-scope fixtures passed.
- Actual release.ps1 preflight refused the committed null review binding as intended;
  PowerShell parsing and git diff --check passed.
- The callback fixture initially encountered macOS /var's symlink with default TMPDIR;
  rerun with TMPDIR=/private/tmp passed without any production gate change.

The synthetic record replay adapts only native path spelling to the temporary local
filesystem. It is not native GUI/SDK evidence. No native build, Store submission,
source/archive publication or site change was performed. Source/license applicability,
current full native app PE observations, final runtime selection and both actual
installed release identities still require root review and a fresh native Windows run.
